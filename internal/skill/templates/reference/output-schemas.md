# figctl output schemas

Generated by `make gen` from the figctl command tree. Do not edit.

Every command prints one envelope. `data` is the command's own payload;
the fields below are its shape. Run `figctl schema <command>` for the
machine readable JSON Schema of any payload.

## The success envelope

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `schemaVersion` | integer | yes |  |
| `command` | string | yes |  |
| `profile` | ProfileInfo or null | yes |  |
| `profile.name` | string | yes |  |
| `profile.handle` | string |  |  |
| `file` | FileInfo or null | yes |  |
| `file.key` | string | yes |  |
| `file.name` | string |  |  |
| `file.version` | string |  |  |
| `file.lastModified` | string |  |  |
| `data` | object | yes |  |
| `truncated` | boolean | yes |  |
| `nextCursor` | string or null | yes |  |
| `hints` | array of string | yes |  |

Read `hints` on every call: they say what was degraded, truncated, or what
to run next. `nextCursor` is non-null when more rows exist.

## The error envelope

Errors are printed on stdout in JSON mode with a non-zero exit code.
Switch on `error.code` and follow `error.hint`.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `schemaVersion` | integer | yes |  |
| `error` | ErrorBody | yes |  |
| `error.code` | string | yes |  |
| `error.message` | string | yes |  |
| `error.hint` | string |  |  |
| `error.retryAfterSeconds` | integer |  |  |
| `error.httpStatus` | integer |  |  |
| `error.details` | object |  |  |

Exit codes: 0 success, 1 runtime or API error, 2 usage, 3 auth, 4 not found,
5 rate limited, 6 partial success (the data is still on stdout, and the
items that failed are in `data.failures`).
